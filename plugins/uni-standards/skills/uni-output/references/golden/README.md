# Golden samples

One approved example per deliverable type. **Anonymised.** These are what `uni-output` and `uni-output-qa` compare a draft against.

Prose rules drift as they get reworded. A file that says "match this" does not. **A sample outranks any prose rule above it** - that is the point of having them.

## The six

| File | Deliverable | Format | Source |
|---|---|---|---|
| `proposal-audit.md` | PPC audit and proposal | Notion | anonymised from a real UNI proposal |
| `analytics-audit.md` | Analytics and tracking audit | Google Doc | anonymised from a real UNI audit |
| `creative-brief.md` | Creative brief, full batch and short form | Notion | anonymised from a real UNI brief |
| `weekly-report.md` | Weekly portfolio roll-up | text message | UNI house format |
| `monthly-report.md` | Monthly per-brand review | markdown, exported plain to Google Doc | UNI house template |
| `text-message-update.md` | Team communication | Slack / ClickUp | UNI house template |

## Every sample carries a Hard requirements block

At the bottom of each file, a numbered list of what is mandatory for that deliverable type. The sample shows the shape; the hard requirements say which parts are not negotiable.

## Before a new sample lands here

1. **Anonymise.** Replace client name, ad account IDs, real spend and revenue, and any person's name or contact detail. Keep the *shape* of the numbers - a report with `$X` everywhere teaches nothing about how we present figures. Use plausible substitutes and say in the header that the data is substituted.
2. **Strip all pricing.** Fees, retainers, rates, package tiers. Media spend is performance data and stays; commercials never appear.
3. **Sean signs off.** A golden sample is a standard. It goes in only if he would be happy for every client to receive it.
4. **Write the Hard requirements block.** A sample without one is a nice document, not a standard.
